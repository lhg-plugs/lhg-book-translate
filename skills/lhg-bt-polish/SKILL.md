# lhg-bt-polish：译者体润色

> 目标：不改变原意，只让中文更像中文。
> 核心纪律：**润色不许改变原意**。拿不准的改法标 `[待确认]` 交给用户，不许自作主张"优化"掉原文信息。

## 1. 何时使用

- 全书初译完成、审计 blocker 清零后 → 跑本 skill 做最后一遍语言打磨
- 用户说"译文都对，但读起来别扭"时 → 直接跑本 skill
- 审计还没跑、术语还不统一时 → 先回去跑 lhg-bt-audit，润色救不了术语混乱

## 2. 输入与输出

- **输入**：`translated/` 下的译文（可全书、可单章）+ 档位（默认轻量，`--deep` 深度）
- **输出**：润色后的译文 + 润色说明（改了哪类问题、改了几处）

## 3. 档位说明

- **轻量档（默认）**：只动翻译腔重灾区，不动句式结构。快，适合初稿/时间紧。
- **深度档（`--deep`）**：逐段给改写候选——每个拗口段落出 2 个改写版本，用户挑。慢，但出出版级文字。

## 4. 第一步：定位重灾区（先跑脚本）

跑审计脚本的翻译腔 5 条规则，按命中密度给章节排个序，先改重灾区：

```bash
python3 scripts/audit/translation_audit.py --target <项目目录> --format json
```

看 `BT-LIT-*` 的分布，命中最多的 3 章优先润色。

## 5. 第二步：去翻译腔四件套

### 5.1 降"的"字密度
"的"字密度是欧化句式的第一信号。改法：
- "对于…的…"结构能删就删："对于模型的训练的过程"→"训练模型的过程"→"模型训练过程"
- 定语过长改成判断句："这是一个由三位研究人员在2024年发表的重要的发现"→"三位研究人员在2024年发表了这一重要发现"
- 保留必要的"的"：表示所属、强调时不删（"我的书"不许改成"我书"）

### 5.2 拆超长句
- 一个句子超过 60 字且含 2 个以上逗号，考虑拆成两句。
- 拆分点选在逻辑转折处（"但是""因此""而"），不许把因果关系拆丢。
- 拆完读一遍：两句之间的逻辑连接词还在吗？

### 5.3 被动改主动
- 英文被动句凡中文有主动说法的一律改："这项技术被广泛应用于…"→"这项技术广泛应用于…"
- 保留被动的两种情况：施事者未知且重要（"窗户被打破了"）、中文习惯被动（"被称为""被誉为"）。
- "被…所…"结构一律改掉，这是翻译腔重灾区。

### 5.4 删"进行"式
- "进行分析/进行讨论/进行验证"→"分析/讨论/验证"。"进行"后面跟的动词直接提前当谓语。
- 类似的名物化结构一起改："做出…的决定"→"决定"，"给予…支持"→"支持"。

### 5.5 统一语气（全书级）
- 称谓统一：全书"是"你"还是"您"，定一个。
- 口语书面体统一：科普书可以活泼，学术书必须书面——一章之内不许跳变。
- 连接词统一："但是/然而/不过"选一套常用的，不许三章三种风格。

## 6. 第三步：通读定稿

1. 润色后通读全书（时间紧就每章读首尾两段），确认语气统一、没有改漏。
2. 最后跑一遍完整审计：blocker 必须为零；翻译腔 warning 应该比润色前明显减少。
3. 输出润色说明：改了哪四类问题各几处、深度档附改写版本对照表。

## 7. 反模式（这些做法一定翻车）

- **为顺而改意**：把"可能"改成"肯定"让句子更顺——这是篡改，不是润色。
- **动术语**：润色时觉得"神经网络"不好听改成"类脑网络"——术语是铁律，润色不许碰 `glossary.md`。
- **轻量档重写整段**：轻量档只改四件套，重写是深度档的活，别越界。
- **润色完不复查**：改完必须重跑审计，润色引入的新问题（如拆句拆丢逻辑）并不少见。
- **一句话翻三遍**：反复打磨同一句超过三遍，边际收益为零——定稿，走人。

## 8. 自检与反馈

质检门（润色交付前自查）：

- [ ] 审计脚本翻译腔 5 条规则命中数比润色前下降（至少降一半）
- [ ] 无新增 blocker（润色没引入术语/标点问题）
- [ ] 全书称谓、语气统一（抽查每章开头）
- [ ] 深度档：每个改写版本注明了"改了什么、为什么"
- [ ] 无 `[待确认]` 残留（或已汇总给用户）

标准冒烟用例：用 `fixtures/trans-good/translated/` 为参照——读起来像中文原创，找不出翻译腔。

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-book-translate/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

## 9. 附：润色改写对照实例库

### 9.1 "的"字瘦身
- 改前：对于模型的训练的过程中的数据的质量的问题，我们进行了深入的分析。
- 改后：我们深入分析了模型训练过程中的数据质量问题。（4 个"的"→1 个）

### 9.2 被动改主动
- 改前：实验结果被证明了是可靠的，被广泛地引用了。
- 改后：实验证明结果可靠，引用广泛。（删"被"，删"地"）

### 9.3 "进行"删除
- 改前：我们对三个模型进行了训练，并对结果进行了比较。
- 改后：我们训练了三个模型，并比较了结果。（"进行"直接删，动词提前）

### 9.4 长句拆分
- 改前：在过去的十年里，随着计算能力的提升和数据的积累，深度学习，作为机器学习的一个分支，在图像识别和自然语言处理等领域取得了突破性的进展，引起了学术界和工业界的广泛关注。（95 字）
- 改后：过去十年，算力提升、数据积累，深度学习迎来突破。作为机器学习的重要分支，它在图像识别、自然语言处理等领域进展显著，引发学术界与工业界广泛关注。（拆成三句，每句一个意思）

### 9.5 欧化句式
- 改前：在很多情况下，人们倾向于认为，更大的模型意味着更好的性能。
- 改后：很多人觉得，模型越大，性能越好。（"在…情况下""倾向于认为"都是翻译腔）

## 10. 附：润色检查清单（逐章打勾）

- [ ] 本章"的"字密度达标（审计脚本 BT-LIT-001 无 warning）
- [ ] 无"进行+X"结构残留（全文搜索"进行"逐个确认）
- [ ] 无"被…所…"结构
- [ ] 超过 60 字的句子已全部复查（该拆的拆了）
- [ ] 段落开头不全是"在…""对于…""随着…"（超过 3 段雷同开头就改）
- [ ] 本章术语与 glossary.md 一致（润色没碰术语）
- [ ] 大声读一遍本章开头结尾，不拗口

## 11. 附：语气统一操作手册

### 11.1 开工前定调子（写进项目说明）
- 读者是谁：专业人士 / 业余爱好者 / 学生——三种读者的用词深度完全不同。
- 口吻：学术严谨 / 科普活泼 / 文学优美——选一种，全书执行。
- 人称：第二人称"你"拉近距离，第三人称"读者"保持距离——定一个。

### 11.2 执行中守调子
- 每章开头结尾大声读一遍：跟上一章的调子像吗？
- 连接词库：全书固定一套（"但是/因此/而"），不许这章"然而"下章"不过"。
- 幽默处理：原文的幽默能翻就翻，翻不出就直译加注——不许为了"活泼"自己加梗。

### 11.3 交付前验调子
- 随机抽 5 章，每章读第一段——5 段像一个人写的，才算过关。
- 找没参与翻译的人读 10 分钟：问他"觉得译者是个什么样的人"——描述前后矛盾说明语气劈叉了。

## 12. 附：润色常见过度清单（别做过头）

- 把作者的长句风格全拆成短句：有的作者就是爱用长句（文学类），拆光了就没有作者味道了——学术书大胆拆，文学书谨慎拆。
- 把专业术语"润"成大白话：术语是准确性的锚，润色不许降维术语。
- 统一句式：全书都改成"主谓宾"短句，读起来像说明书——句式要有节奏变化。
