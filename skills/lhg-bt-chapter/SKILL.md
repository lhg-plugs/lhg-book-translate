# lhg-bt-chapter：章节翻译三遍工作法

> 目标：把一章原文变成忠实、通顺、可直接交付的中文。
> 核心纪律：**术语表是铁律，标点是门面**。译文里出现一个英文逗号，读者对译者专业度的信任就掉一格。

## 1. 何时使用

- 术语表已锁定，开始逐章翻译时 → 每章都跑本 skill
- 用户只给了一章/一段散文要翻译时 → 跑本 skill 的第 3-5 步（跳过项目初始化）
- 译文已经写完、只想润色时 → 跳过本 skill，用 lhg-bt-polish

## 2. 输入与输出

- **输入**：`source/` 下的一个原文章节文件 + 已锁定的 `glossary.md`
- **输出**：`translated/` 下同名译文文件 + `translation-log.md` 的一行记录（含本章新术语登记）

## 3. 第一遍：直译（忠实优先，不管中不中文）

1. 逐句翻译，不合并、不拆分、不调整语序——先保证**一句不漏、意思不走样**。
2. 术语严格按 `glossary.md` 的统一译法；表外术语标 `[待确认:原文]` 先翻过去，不许自创译名。
3. 数字、公式、代码、专有名词原文保留格式，只翻译自然语言部分。
4. 这一遍的译文可以生硬，目标是"可对照校验的底稿"。

## 4. 第二遍：意译（通顺优先，中文语序重组）

在直译稿上改，允许且鼓励以下操作：

1. **拆长句**：英文从句套从句的长句，按中文习惯拆成 2-3 个短句。判断标准：一个句子读两遍才懂，就拆。
2. **调语序**：英文"主句+长长的原因状语"改成中文"因为…，所以…"；时间地点状语前置。
3. **换句式**：英文被动句凡中文有主动说法的一律改主动（"这本书被广泛阅读"→"这本书拥有大量读者"）。
4. **减连接词**：英文的 which/that/where 引导的定语从句，能改成中文偏正短语就改（"the model which was trained on…"→"经…训练的模型"）。

但有三条红线不许碰：不增删原文信息、不合并两个独立论点为一句、不把作者的判断语气（"显然""可能"）改掉。

## 5. 第三遍：对照校（一句不漏 + 标点规范）

1. 原文译文逐段对照：每段原文都有对应译文吗？有没有漏译整句？（漏译是 blocker）
2. 术语抽查：本章出现的所有术语表术语，译法与 `glossary.md` 一致吗？（跑审计脚本的术语规则自动查）
3. 标点规范（出版级门面）：
   - 中文段落只用全角标点：，。；：？！""''（）
   - 英文半角标点 `,.;:?!""` 出现在中文句子里，一律改掉（数字小数点、网址、代码块除外）
   - 直引号 `"` 改成弯引号 ""，单引号 `'` 改成 ''
   - 括号统一用全角（），除非括号内是纯英文/代码
4. 数字格式：全书统一——科技书建议阿拉伯数字 + 中文单位（"5 千米"）；人文书可按出版社规范。一章之内不许混用。

## 6. 收尾：日志与新术语登记

1. 在 `translation-log.md` 追加一行：`YYYY-MM-DD 第X章 译完（约 NNNN 字），新术语：A→a、B→b（待确认）`。
2. 本章发现的表外术语：已标 `[待确认]` 的汇总成清单交给用户，一次性确认后进术语表。
3. 跑一遍审计脚本看本章：`translation_audit.py --target <项目目录>`，本章引入的 blocker 当场修掉。

## 7. 反模式（这些做法一定翻车）

- **一段流直译**：英文长句不断句直接翻，译文比原文还难懂——这是机翻，不是翻译。
- **术语跟着感觉走**：这章"神经网络"下章"类神经网络"，读者以为是两个概念。
- **标点随手敲**：中英标点混用是译文"廉价感"的最大来源，校对时必须逐类扫一遍。
- **漏译整句**：长段落里丢一句是最常见的事故，对照校时数句子数量是最笨但最有效的方法。
- **自作主张加料**：原文没有的例子、解释不要加；想加必须标 `[译者注]` 并经用户确认。
- **一次翻完全书再校对**：错误会在全书复制粘贴。一章一校对，前面章节定的调子后面沿用。

## 8. 自检与反馈

质检门（单章交付前自查）：

- [ ] 原文每句话都有对应译文（数句子数量对得上）
- [ ] 本章所有术语与 `glossary.md` 一致，无 `[待确认]` 残留（或已汇总待确认）
- [ ] 无英文半角标点混入中文句子（审计脚本 BT-PUNC 三条规则零命中）
- [ ] 无超长未断句（审计脚本 BT-LIT-004 零命中）
- [ ] `translation-log.md` 已追加本章记录

标准冒烟用例：用本仓库 `fixtures/trans-good/translated/` 的章节为参照——术语统一、标点全角、句式短平快。

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-book-translate/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

## 9. 附：改写对照实例库

### 9.1 拆长句
- 原文：The model, which was trained on a massive dataset collected from millions of users over several years, achieved remarkable results.
- 直译：这个在多年间从数百万用户收集的海量数据集上训练的模型，取得了显著的结果。（53 字，一口气读不完）
- 意译：该模型在海量数据集上完成训练，取得了显著成果。数据集历时多年，采集自数百万用户。（拆成两句，先说事，再补背景）

### 9.2 调语序
- 直译：他决定离开，因为他对这个项目失去了信心，在经历了三次失败之后。
- 意译：在经历了三次失败、对项目失去信心之后，他决定离开。（原因前置，符合中文习惯）

### 9.3 被动改主动
- 直译：这项技术被广泛应用于医疗领域。
- 意译：这项技术在医疗领域应用广泛。（"被"字删掉，意思不少）

### 9.4 减连接词
- 直译：这是一个能够自动学习用户偏好的系统，它可以根据用户的反馈调整推荐策略。
- 意译：这个系统能自动学习用户偏好，并根据反馈调整推荐策略。（"这是一个…的…"句式是翻译腔重灾区）

## 10. 附：标点速查表

| 场景 | 正确 | 错误 |
|---|---|---|
| 中文句号 | 。 | . |
| 中文逗号 | ， | , |
| 中文引号 | "…" '…' | "..." '...' |
| 中文括号 | （） | () |
| 中文冒号/分号 | ：； | :; |
| 省略号 | ……（两个） | ... 或 。。。 |
| 破折号 | ——（两个） | -- 或 —（一个） |
| 数字小数点 | 3.14（保留半角点） | 3。14 |
| 网址/代码 | https://example.com（保留原样） | 强行改全角 |

## 11. 附：数字格式决策树

1. 科技/社科书 → 全书阿拉伯数字（"5 千米""2024 年"），这是行业惯例。
2. 文学/历史书 → 按出版社规范；无规范时，10 以下用汉字（"三天"），10 以上用阿拉伯（"120 人"）。
3. 一章之内不许混用两种写法；全书统一在开译前定好，写进项目说明。

## 12. 附：长难句处理手册

### 12.1 定语从句三招
1. **前置**：短定语直接前置——"the book that changed my life"→"改变我人生的那本书"。
2. **拆句**：长定语拆成独立句——"The theory, which was proposed in 1980 and later refined by several researchers, remains influential."→"该理论 1980 年提出，后经多位研究者完善，至今仍有影响力。"
3. **转状语**：定语含因果转成"因为/由于"——"a model that fails when data is scarce"→"由于数据稀缺时会失效，该模型…"

### 12.2 状语从句前置
英文习惯"主句+because…"，中文习惯"因为…，主句"。翻译时先找连词（because/when/although/if），把从句整个搬到句首，再翻主句。

### 12.3 被动语态判断树
1. 施事者明确 → 改主动。
2. 施事者不明但不重要 → 用"人们/研究"补主语或改无主句。
3. 施事者不明但重要 → 保留被动，但删"被…所…"结构。
4. 中文习惯被动（"被称为""分为"）→ 保留。

## 13. 附：常见漏译点清单

对照校时重点数这几类，最容易漏：
- 插入语（破折号/括号里的补充说明）
- 举例（such as / e.g. 后面的例子只翻了一半）
- 转折句的后半句（but/however 后面的才是重点，最容易漏）
- 图表标题与图注（正文翻完就停，图注忘了）
- 脚注与尾注（单独成段，容易被跳过）
