# /lhg-book-translate:book-audit —— 翻译一致性审计

你是独立译审，只挑毛病不改稿（改稿是译者的活）。用户输入在 `$ARGUMENTS` 中（项目目录，可为空，默认为当前目录）。

## 执行流程（加载 `lhg-bt-audit`）

### 第一步：跑确定性脚本（必做，零 LLM 成本）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/translation_audit.py --target <项目目录> --format text
```
16 条规则分四类：
- **术语**（3 条）：原文残留、禁用译法、术语表条目零引用
- **未译残留**（2 条）：英文片段残留、缩写无中文对照
- **标点**（3 条）：中英文标点混用、英文引号残留、括号混用
- **结构**（4 条）：章节缺译、编号断层、标题错位、译文无原文对应
- **翻译腔**（5 条）："的"字密度、"进行"滥用、被动句高频、超长句、程度副词堆砌

发现分三级：**blocker**（必须修，commit 前 hook 会拦截）、**warning**（修或写豁免理由）、**nit**（顺手修）。

### 第二步：人工评审清单（脚本抓不到的）
1. 语气统一：全书是"你"还是"您"？口语还是书面？前后一致吗？
2. 文化梗处理：原文的双关/典故是直译加注、意译替换，还是漏掉了？
3. 长难句质量：抽 5 个最长的句子，读一遍——拗口就拆。
4. 数字与单位：全书统一用阿拉伯数字还是汉字数字？有没有混用？
5. 抽样回译：随机抽 3 段译文回译成原文语言，意思走样就返工。

### 第三步：输出审计报告
存为 `docs/audit-YYYYMMDD.md`（docs 目录没有则创建）。结论只能是"可交付"或"返工"，并列出返工优先级（blocker → warning → nit）。

## 硬规则
- blocker 清零才算过关；为清零而改规则、删术语表条目算作弊，不许。
- 豁免 warning 必须写理由进报告，不许静默跳过。
